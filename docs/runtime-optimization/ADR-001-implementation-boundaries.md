# ADR-001：保留现有 writer，先交付可独立验证的性能改进

日期：2026-10-25。状态：**当前实现边界决定；不是生产主端接管的最终存储 ADR。**

## 依据

现有分支类型检查与 1,409 项单测通过。现有 repository 已有 JSONL、revision、删除和替换保护，不能通过重写来换取表面的架构一致。新 worktree 与另一个 agent 独立，所有接管改造必须在本分支证明，不默认迁移用户 profile。

## 决定

1. 保存准备采用结构见证而非对象引用缓存，兼容后台原地修改；保留完整 fallback。后续若接入稳定 dirty revision，再减少全历史字段扫描。
2. 历史读取选择独立 worker 的可重建 SQLite read model。它只服务有界读取，不成为会话事实源，现有源文件不改写。
3. 只读分页作为独立 UI 入口先接通，防止在尚未建立主端 patch writer 时，把部分历史接入旧全量保存链。
4. 操作账本先实现私有、带校验链的追加日志，用隔离测试明确接收和未知状态；生产选择仍需与 SQLite 操作事务库 spike 比较。使用 SQLite 做派生读模型不等于完成了这一对比。
5. 无窗口 coordinator 先依赖注入 adapter 端口，不默认劫持三引擎 IPC 或 renderer 事件。它不是自建编码 Agent。
6. legacy 发送/审批/重试 owner 保持原状；没有实现迁移和全入口 fencing 前，不暴露能够在用户 profile 开启 managed writer 的设置或 IPC。

## 未通过的门槛

G0 只有基线/编码微基准/生成 UI 数据，完整链路基准待补；G1 的生产持久化、独占恢复、兼容下限待冻结；G2 的真实三引擎接管未开始；G3/G4/G5 均未通过。

## 安全回退

编码优化可切回原编码准备；只读分页入口可移除，JSONL 和原打开/导出链不受影响。控制内核没有生产 owner，因此移除该实验模块不会迁移或回退任何用户数据。不要把这些简单回退方法套用到未来已经切换 writer 的 profile。
