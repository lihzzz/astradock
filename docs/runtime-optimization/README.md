# AstraDock 多引擎运行时与性能优化方案

日期：2026-10-25（Asia/Taipei）。状态：**在独立分支 `codex/runtime-optimization` 分阶段实现中，尚未全部完成。**

先看[当前实现与边界](implementation-evidence.md)、[状态记录](implementation-status.md)与[ADR-001](ADR-001-implementation-boundaries.md)。只读分页和保存编码复用已接入桌面；命令/运行控制内核仍是隔离测试模块，不是三引擎主端接管已完成。

本方案覆盖用户指定的六项：会话/执行/运行时分层、命令回执与状态机、Provider 能力声明、原始协议回放、摘要与详情分离及分页/按需订阅、独立服务边界与共享客户端。它们分别解决可靠性、可维护性、测试质量、性能和多端扩展，**不是六项性能优化，也不是六个已确认缺陷**。

## 核心取舍

- 基于现有 Electron + React + TypeScript + 三引擎适配渐进改造，不为对齐 T3 Code 重写项目或引入 Effect。
- 保留已实现的 JSONL 增量存储、逻辑身份、删除/替换屏障、checkpoint 调度、虚拟化和流式批处理。
- 优先交付可量化、可独立回退的桌面性能改进；可靠性重构通过单写者、耐久和真实引擎门槛后再接管。
- JSONL 会话历史继续保留；查询索引、命令/运行账本各有明确职责，不出现两个可独立修改会话的权威来源。
- 新运行时先驻留 Electron 主端的可独立服务模块；拆进程、网络传输、Web/手机端不作为桌面优化的前置条件。
- 自建编码 Agent、新模型、新订阅集成、VPS 部署、真实模型费用和发布不在本次授权范围内。

## 六项与交付映射

| 主题 | 主要收益 | 对应工作包 |
| --- | --- | --- |
| AppThread / Run / ProviderSession 分层 | 状态正确性、可维护性 | OPT-01、OPT-06、OPT-08 |
| 命令 ID / 回执 / 状态转换 | 防重复、可恢复、可解释错误 | OPT-05、OPT-06、OPT-08 |
| Provider 能力与降级 | 多引擎行为一致、降低适配成本 | OPT-01、OPT-06 |
| 原始协议回放 | 可复现竞态、防回归 | OPT-02、OPT-09 |
| 摘要/详情、分页、按需订阅 | 降低读取、序列化、传输与渲染开销 | OPT-03、OPT-04、OPT-07 |
| 独立服务边界与共享客户端 | 为多客户端复用做准备 | OPT-06、OPT-07；实际远程接入为 OPT-10 |

优先级是交付依赖和风险次序，不是缺陷严重度。OPT-00 后再依据数据决定哪些优化值得实施。
