## 删除恢复与批量操作证据

- 启动时先读取全部有效删除记录，再逐条清理。单项 unlink 或提交失败保留该会话屏障与错误记录，不阻止无关会话加载、保存；不把尚未持久化成功的 committed 状态当作删除成功。
- `DELETE_INCOMPLETE` 保持会话停用，可按原逻辑身份重试；所有快照已移除、但最后提交失败时也可继续。`ALREADY_DELETED` 返回 skipped。损坏删除记录明确报错，修复后可重新读取，不因一次失败永久缓存初始化错误。
- 删除意图写盘失败时不停止引擎，并撤销内存屏障。已完成删除后，携带旧运行时 ID 的迟到替换，即使报出不同逻辑身份也会被拒绝。索引监听器异常单独上报，不改变已经成功的源数据保存结果。
- 新增 `sessions:batch-recoveries` 供主 renderer 读取未完成删除；不自动重放整批。操作记录可切换查看，失败项可直接重试，原会话已不在列表中时仍可完成冻结与清理。
- 同一会话的并发批量操作返回 BUSY；取消和完成释放占用。准备应答拒绝重复目标。进度按 250 ms 合并，准备、取消与最终结果立即推送。500 项单元压力用例验证全部结果保留、推送合并与定时器清理；存储调用在该用例中模拟，**不是 500 个真实文件的性能验收**。
- 渲染端区分临时冻结、未完成删除、已完成删除；后续停止失败并成功撤销删除意图时可解除 pending 状态，不能解除 committed 状态。
- `scripts/test-history-ui.cjs` 使用生成数据注入 meta 文件 unlink 失败：原来源不可再读取，重新加载 renderer 后显示恢复任务，点击“重试失败项”完成删除，再次删除正确跳过。该证据结合仓库启动恢复测试；尚未代替三引擎正在运行时的完整删除验收。

## 恢复与删除竞态证据

- renderer 的恢复与重启请求携带原项目和保存的运行时 ID。主进程从本地源元数据确认引擎与逻辑身份，在异步启动前登记新运行时；不采用 renderer 自报的逻辑会话键。删除意图同时记录尚未写入快照的新运行时 ID，取消全部恢复登记后逐个等待停止。
- Claude 在 SDK、二进制和 MCP 准备后复核登记状态；权限模式初始化期间也启动事件循环，删除能关闭 query 并等待退出。内部重启复用同一启动路径，等待旧循环结束后再使用原 ID。旧循环只清理自己持有的 Map 条目；重复恢复失败不能移除已有运行时。未保存的源不能重启，但保留原 query。
- Codex 在握手、线程恢复和返回结果前检查运行时；普通停止也等待实际退出。ACP 在协议初始化之前登记子进程，覆盖 `session/load` 与 `session/new` 回退；连接关闭会终止等待中的初始化、认证和加载请求，不继续等到超时。三类引擎在记忆预检完成后、发送前重新检查状态。
- 停止失败时保留原源数据和待停止运行时。撤销删除意图不重新激活已取消的恢复登记；进程退出后可以重新发起恢复。
- `electron/src/ipc/session-runtime-races.test.ts` 的 22 项测试通过：覆盖 SDK/二进制准备中删除、协议握手中删除、结果已返回但新快照未落盘、ACP 重启回退、迟到发送、停止失败、Claude 权限请求和内部重启；另包含尚未保存草稿时删除整个项目的 6 项测试。Codex/ACP 使用真实 Node 子进程、stdio 和退出信号，由本地 fixture 模拟协议；Claude 使用 SDK query fixture。未调用真实供应商 agent 或读取用户会话，不能据此宣称三引擎真实服务的端到端验收完成。
- 会话仓库另有 3 项专项验证未启动运行时取消、停止确认前保留文件，以及回滚后的登记失效与重试。

## 渲染端恢复、重试与持久化证据

- 三引擎恢复统一遵循“启动 → 持久化替换 → 采纳运行时 → 等待目标引擎视图就绪 → 发送”。不再用固定 50 ms 延迟假定输入视图已挂载。导航离开后再返回、组件卸载和删除都会取消尚未发送的恢复；迟到结果停止自己启动的运行时，不向其他会话写消息或切换其焦点。
- 持久化失败保留原会话 ID；已提交的替换则同步列表中的新 ID，即使提交期间用户已导航离开。删除冻结和恢复占用跟随旧、新运行时别名传递，旧 ID 退休后不再自动保存。追加失败转完整保存前重新检查删除与退休状态。
- 未发送文字、显示文本和图片保留在原会话队列，不写入已发送历史。现有“Send next”支持恢复已停止会话，复用同一消息 ID；连续点击仅启动一次，撤销排队后不再发送。点击实际发送时更新消息时间和显示顺序。
- 恢复占用只持续到目标视图接管并发起发送，ACP 的整轮 prompt 等待不再阻止流式自动保存和导出。首次发送失败停止该运行时，后续排队内容保留等待显式操作，不在错误后自动继续发送。停止失败单独报告，renderer 也不会将未完成恢复视为可继续排队发送。
- 手动重启同样先保存再采纳新 ID；MCP 探测和状态刷新检查原目标。Claude 回退先确认本地存在对应检查点，避免在找不到聊天截断点时先改写文件。
- `src/hooks/session/useSessionRevival.test.ts` 的 35 项测试和 renderer 持久化 / 删除屏障的 10 项测试通过。测试覆盖三引擎在启动、保存、视图等待期间的取消，保存失败重试、图片保留、重复点击、排队撤销、发送失败，以及手动重启与 MCP 状态刷新。
- `pnpm exec electron scripts/test-session-recovery-ui.cjs` 的 10 组检查通过：在独立临时配置中运行真实 React StrictMode、`useEngineBase`、恢复与队列 hooks 及 DOM 点击，覆盖三引擎的失败重试、目标视图重置、离开后返回、卸载，并检查 Claude 原 ID 恢复。测试禁用网络，使用生成历史和模拟引擎 IPC；这是渲染生命周期证据，不是供应商 agent 的真实服务验收。
- 保留的未发送队列仍为进程内状态，不承诺应用退出后恢复。旧运行时迟到写入、遗留多快照及同 ID 的逻辑身份变化已有后端与界面专项；实际 agent 的失败与退出、500 个真实文件的取消和性能仍需完整联测。

## 主进程持久化运行时替换证据

- 替换记录位于 `sessions/.replacements`，独立于索引缓存。prepared 阶段只展示原快照；新 JSONL 与 meta 完整写入后，committed 记录作为提交点。初始记录、来源文件、meta 或提交记录写入失败，均保留原来源；回滚失败时隐藏尚未提交的新来源，启动后继续回滚。
- 显式替换链持久记录运行时与逻辑身份变化。旧 ID 的 save、append、update-meta、恢复和新启动均检查主进程状态，改报逻辑身份不能绕过退休限制。相同 ID 在其他项目不受影响；替换不能覆盖已有目标文件、其他逻辑会话或改变引擎。
- 旧、新逻辑键与运行时 ID 同时排队。替换提交期间开始删除时，删除继续解析最新来源、收集整条替换链和已登记进程，并持久拒绝链中所有 ID 的迟到写入。已接管的新运行时仍可使用原登记；旧运行时登记不再可用。
- 提交后的旧文件清理失败不撤销新来源。列表、历史扫描和重建最后发布检查都排除退休快照；启动再次清理旧文件。查询中的旧快照通过来源事件失效，即使逻辑键保持不变。
- 替换同时退休已经存在的同逻辑会话快照；回退到更早消息后，不按遗留快照较新的时间戳重新采纳它。普通保存先读取原身份并共同加锁，遗留别名改报身份的迟到写入仍会排在替换之后并被拒绝。目标源文件缺失也不能覆盖已提交的替换记录。
- 同 ID 的逻辑身份变化同样经过替换事务：备份原有 JSON / JSONL / meta，prepared 阶段通过备份提供列表、原文和索引读取。保存或追加失败时恢复原格式，当前进程登记保持有效；连续身份变更分别保留重映射记录。早期不含退休列表与备份字段的 v1 记录仍可读取。
- 删除和项目删除会清理对应备份，清理失败保持 DELETE_INCOMPLETE。启动先建立并恢复删除屏障，再处理替换回滚，避免备份复活已删来源；备份创建失败不改原文件，提交记录前崩溃留下的孤立备份目录可在启动时清理。
- `session-replacement.test.ts` 的 27 项测试通过，使用真实临时源文件与写盘故障注入：覆盖跨重启迟到写入、归档保留、连续替换、目标冲突、损坏记录修复、非法身份拒绝、并发替换及删除、索引重建期间提交；另覆盖遗留快照回退、同 ID 保存/追加、原格式恢复、备份失败与清理、删除中断优先恢复、旧记录兼容及提交记录不可覆盖。
- 完整应用的 `scripts/test-history-ui.cjs` 通过实际 main / preload / renderer 执行生成会话的跨 ID 与同 ID 身份替换：原 ID、遗留别名和旧逻辑身份的保存均返回 SESSION_REPLACED；只列出一个保留归档状态的新来源，历史结果解析为最新身份；重新加载后，后续部分删除恢复及整个项目删除仍通过。未启动实际供应商 agent。
- 本轮全量测试为 614 项通过、1 项跳过，`pnpm build:electron` 通过；Electron 类型检查与上一轮诊断一致。以上仍不是实际供应商 agent 或跨平台安装包验收。

## 整个项目删除证据

- 项目删除使用独立于派生索引的 `.project-deletions` 持久记录。先拒绝新启动和写入，等待已进入的源文件写队列，取消恢复及未保存草稿的登记，确认进程退出后清理 Harnss 的会话源目录。保留项目工作目录；源数据提交后才移除项目目录表中的行。
- 初始意图写盘失败不停止进程；停止失败且尚未清理文件时撤销项目屏障，但不激活已取消的启动。目录部分删除、提交记录失败和目录表更新失败均保留可重试状态。启动按项目恢复，一项锁定目录不阻塞无关项目。项目目录表的读改写在同一同步步骤内原子提交，等待进程退出期间其他项目的重命名不会丢失。
- 历史请求在验证主 renderer 身份后等待仓库初始化。项目屏障变化立即使查询失效，并从后续查询目录中过滤该项目；索引扫描和最终发布再次读取持久项目记录。撤销意图期间读到 ENOENT 不误报数据损坏。整个项目已经停用时不再单独恢复其会话删除任务。

## 语义模型与实际运行证据

以下配置已写入 `shared/lib/embedding-model.ts`，属于当前实现候选，**仍需 G2 召回集与大数据门槛验收**。

| 项目 | 固定配置 |
| --- | --- |
| 模型 | `Xenova/multilingual-e5-small` |
| revision | `761b726dd34fb83930e26aab4e9ac3899aa1fa78` |
| 编码 | 同 revision 的 XLM-R tokenizer；q8 ONNX；384 维 Float32；mean pooling + L2 |
| 输入规范 | 查询 `query: `；正文 `passage: `；最大 512 tokens |
| 分块 | 含前缀与特殊 token 的输入最多 384 tokens；正文重叠最多 64 tokens；保留原始 UTF-16 位置，优先段落和可完整容纳的代码块 |

| 生命周期 | 语义默认关闭；开启才下载；可暂停/恢复；关闭保留磁盘缓存；清除缓存同时关闭功能；推理实例闲置 5 分钟释放 |

模型维度、输入前缀、512-token 限制及 MIT 许可证依据[原模型说明](https://huggingface.co/intfloat/multilingual-e5-small)；ONNX 转换来源见[转换模型说明](https://huggingface.co/Xenova/multilingual-e5-small)。模型调用固定 revision，不运行远端模型代码或上传会话正文。

- `scripts/test-semantic-runtime.cjs` 在 Electron 40.4.0 / Node 24.13.0 / macOS arm64 下，通过主历史 worker → 独立 embedding worker → SQLite → 原消息片段的实际链路。下载缓存预热后，小型 10-entry 数据集准备 944–1486 ms，热查询 9–10 ms。

### 一致性修复

- 手动写入等待留存请求完成，服务不可用或写失败不会返回成功；失败不毒化后续写入队列。

- 召回返回后复核会话、发送轮次、全局开关和项目隔离，避免旧请求覆盖新上下文。
- 记忆 IPC 统一验证主窗口主 frame；新增保存入口验证项目存在、显式范围及内容长度。
