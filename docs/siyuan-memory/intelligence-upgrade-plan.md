## 0. 已确认范围与决策记录

用户确认保留思源存储，重点借鉴 ai-memory 的提炼与检索，并增加记忆使用追踪、渐进式上下文、知识有效性与纠错、结构化跨引擎交接。本计划将其固定为六项，不随实施自行扩展。

| 编号 | 功能 | 交付定义 | 明确不等同于 |

| F4 | 渐进式上下文 | 索引、摘要、正文按需提供，共享明确预算 | 每次全文注入、旧摘要代替当前正文 |

## 1. 不可变原则与非目标

### 1.1 必须保持的边界

1. **思源是知识正文唯一权威来源。** 不新增 Markdown/Git 知识库、独立正文数据库、离线摘要库或正文补写队列。
2. 思源只通过现有已验证的本机公开 HTTP/MCP 接口访问；不直接读写 `.sy`、内部 SQLite，不放宽 loopback、重定向、Token 或响应预算限制。
3. 当前会话 Agent 负责语义提炼和必要的查询建议；应用执行确定性筛选、校验与排序。没有新增模型服务、Embedding、LLM reranker 或隐式网络出口。
4. 总开关关闭后禁止新的记忆读写；仅关闭某项增强不扩大授权。思源不可用时聊天继续，明确标记不可用，不把故障当成空库。
5. 项目事实默认留在当前项目；个人范围只接受用户明确表达的跨项目偏好。重复出现不是升级为个人偏好的授权。
6. 现有授权范围内自动追加，不逐条确认、不引入待审批收件箱。用户反馈是一项明确动作，不成为每条自动记忆的批准门槛。
7. 自动操作不删除、改写、搬移用户已有正文。修正和反馈采用可核对的追加关系，保留原始内容。
8. 保留 operationId、精确去重、同目标串行、限额、写后核对、unknown 不重放、changed 不覆盖等保护。新增记录类型不能绕开这些保护。
9. 搜索摘要不是证据；最终使用前重新读取思源正文、校验当前范围和工作空间。跨项目引用也不能绕过范围。
10. 记忆是低优先级参考数据。当前用户要求与仓库规则优先；存储内容不能授权工具、执行命令、改变权限或删除文件。
11. 会话证据只使用可见用户输入、可见结果和可验证的工具事件；不保存或提取模型隐藏推理。任何“引用存在”都不自动证明结论为真。
12. 一次交接不自动标记任务完成、不自动扩大目标引擎权限、不自动提交或切换 Git 状态。
13. 保留普通任务/会话原有持久化与用户显式导出的上下文；它们不是可在思源离线时重新导入的记忆缓存。已进入历史上下文的内容无法追溯撤回。
14. 外部修改与思源写入不能假定存在跨系统原子事务；读取 hash 前后相同不等于原子 CAS，不承诺严格 exactly-once。

### 1.2 本轮明确不做

- Rust 服务移植、第二记忆后端、ai-memory CLI/launcher、跨项目代理 Inbox。
- 新云服务、自动模型下载、向量库、Embedding/LLM 重排序、自动后台经验提炼。
- 自动遗忘删除、自动重写用户笔记、迁移/批量重编全部旧条目、全量复制会话到思源。
- 独立的复杂管理后台、团队权限系统、SSO、公开远程记忆接口。
- 本轮执行真实旧数据清理、打包发布、改变用户凭据或环境。

### 2.1 必须先解决的工程事实

- 当前 MemoryWriteRecord 记录 session/turn 等操作信息，但不是逐消息证据链；memory turnId 与各引擎原生 turnId 不能直接假定相同。
- 当前查询是思源 fulltext + 按范围候选；没有多查询融合或独立语义索引。思源返回顺序的含义必须通过 fixture/版本契约验证，不能直接称为 BM25 分数。
- 当前读取的 2000 UTF-8 字节主要是单次调用预算；新方案必须增加回合级总预算，防止多次调用绕过限制。
- 固定库目前不要求人工摘要；旧配置的 summaryBlockIds 仍在兼容路径，不能把该路径误称为完整自动简报。
- 当前普通正文编码与 normalizeMemoryText 会影响换行；结构化序列化、哈希和解析必须一起设计，不直接拼接任意 Markdown/IAL。
- 当前修正定位主要在原条目所在页有界扫描；跨页关系必须有明确定位及回退策略，不无界扫描全部笔记。
- 当前 AppLayout 负责导出后创建目标会话；新交接必须明确继承 WorkspaceBinding，不能只复制 projectId 后采用当前选中的 worktree。
- 历史验收中的 20/20 是预设中文关键词命中，不是模型自动提炼、自然语言检索、正确使用的端到端结果。
- 仓库指导引用的 `docs/ai-sdk/`、`docs/typescript-sdk-main/`、`docs/agent-client-protocol-main/` 未全部在当前工作区提供；改动协议时以锁定依赖、现有适配器和补齐的一手协议文档核实，不猜测事件能力。

## 3. 目标架构与数据归属

### 3.1 三种数据域，禁止相互冒充

| 数据域 | 权威载体 | 可以存什么 | 不可以存什么 |
|---|---|---|---|
| 长期知识 | 思源专用库、授权项目/个人分类 | 原子结论、条件、简要证据、来源指针、修正/反馈记录 | 完整原始聊天归档、隐私推理、凭据 |
| 任务与会话 | 现有会话 JSONL / task store / session-transfers | 目标、进度、验证结果、工作区、交接 packet 与原有完整导出 | 将旧记忆摘录升级为新的权威知识 |
| 运行元数据 | AstraDock 本地小型文件/内存 | operationId、ID 关系、hash、追踪阶段、耗时、预算、派生目录 | 正文/摘要/检索 query 的离线镜像、可补发正文队列 |

主路径：

```text
当前 Agent 的正常回合
  → 有界来源引用 → 提炼候选 → 旧知识对照 → 程序校验
  → 既有 writer/journal → 思源追加 → 核对结果

问题 + 已授权范围
  → 查询计划 → 思源全文候选 → 融合/类型与条件检查
  → 关系/有效性检查 → 当前正文重读 → 分层预算 → Agent

显式交接
  → 冻结来源会话/任务/工作区 → packet + 原有完整历史导出
  → 创建/复用本次交接目标 → 确认发送 → 接手重新检查现场
```

## 4. 数据契约、格式与兼容

### 4.1 MemoryEntry：内容与操作状态分离

逻辑字段如下。字段是否可缺失由具体判别分支决定，不能用一组全 optional 字段掩盖不完整来源。

| 字段组 | 内容与规则 |
|---|---|
| 身份 | formatVersion、稳定 entryId、思源 blockId；blockId 只有核对成功后才成立 |
| 分类 | 复用六种 MemoryKind 和 project/personal；作用域由宿主推导，模型不能指定任意项目或文档 |
| 结论 | title、一句话 conclusion、必要 detail；一条记录一个独立结论 |
| 条件 | applicability：项目/技术栈/版本/环境/任务条件；未知用明确 unknown，不默认全局适用 |
| 原因/步骤 | decision 可带 rationale；procedure 带前提与步骤；troubleshooting 带症状、处理、验证边界 |
| 来源 | evidenceRefs 的持久化投影、来源类别、conversationKey、可用的 message/tool ID、observedAt、sourceHash |
| 关系 | relatesTo / supplements / corrects / contradicts；只允许已授权、已解析的引用，不接受任意目标路径 |
| 内容版本 | 基于当前正文的 contentHash；写入时 hash 不代表现在的正文未变化 |
| 状态依据 | 反馈/修正事件的引用；有效性在读取时计算，不由模型直接写 active=true |

- `verified/unknown/changed/conflict` 仍表示**写入核对状态**，不得当作知识真伪或用户认可。
- 新结论的来源可区分 `explicit_user_statement`、`observed_tool_result`、`user_attested`、`legacy_unverified`；这些标签说明证据类型，不是概率置信度。
- 某命令 exitCode=0 只能支持该命令成功执行；是否验证了候选结论仍需要明确对应条件。模型自行声称“已验证”不产生 observed_tool_result。
- 不新增依赖模型自评 confidence 的硬批准门槛；硬门槛来自来源可解析、范围、字段、敏感规则、输入预算和写入状态。

### 4.2 思源序列化

1. 将结构化内容序列化成**可读、固定字段顺序的普通文本**，沿用单块安全编码；不把字段拼成模型可控制的 IAL、SQL 嵌入或可执行链接。
2. 一次追加中同时带上应用生成的操作标记、formatVersion、记录类别、kind、hash、entryId 等短属性。属性键、枚举、长度与编码由程序白名单控制。
3. 记录类别至少区分 `knowledge`、`feedback`；反馈不能被全文搜索误当成新的事实结论。
4. 摘要/标题/条件属于思源当前正文，不另在本地保存副本。用户编辑后重新解析；解析失败则回到当前普通正文，并标记 `structure_unavailable`，不能复用旧摘要。
5. 序列化后的**所有可读字段合计**沿用 2000 字符正文上限；不是每个字段各 2000。来源集合和程序属性另有独立上限。
6. 哈希基于版本化的统一规范化规则；旧记录继续使用旧规则核对，禁止一次升级使所有旧 unknown 记录失去核对能力。
7. 在假服务 fixture 和获批真实临时文档验证“编码→追加→读回→解析→hash”往返；失败则不得开放结构化自动写入。
8. 思源属性同样是可被外部修改的不可信数据；`custom-astradock-*` 标记只帮助识别/核对，不构成授权、真实来源或用户批准证明。所有来源与范围仍由宿主重新验证。

### 4.3 EvidenceRef：来源存在与结论正确不是一回事

- 主进程注册可见用户输入、已完成工具事件等，生成不可猜测的 evidenceRef；模型只返回这个引用，不提交自己声称的身份、退出码或成功时间。
- 注册用户来源时使用注入记忆策略之前的原始用户消息；应用提示、召回正文和其他模型转述不能回灌成新的用户要求或独立验证证据。
- registry 绑定 projectId、稳定 conversationKey、runtimeSessionId、memoryTurnId、engineTurnId（如有）、generation、来源类型和 hash；不同引擎的 turn ID 通过显式映射关联。
- `memory_evidence` 只返回当前授权会话中已产生的有界来源句柄和最小片段；不让该工具读取任意会话、路径或系统文件。
- 用户显式选取历史会话做经验整理时，宿主可以建立仅覆盖该来源清单的临时 reviewScope；模型参数不能扩大清单。此模式仍在当前可见回合执行，逐个检查历史来源访问权，结束即撤销；没有该授权就只查询当前会话。
- 当前回合用户消息直接可用；正在流式输出、被拒绝、被中断、尚未结束的工具结果不可声明验证成功。
- 原生事件和已持久化消息尚未建立映射时标记 `pending_mapping`，不伪造 messageId。关闭/替换会话后迟到事件不能补写进另一个会话。
- 来源引用长期只保存指针/hash；被引用会话删除、不可访问、正文变化时标记 `missing/changed/unavailable`，不从 journal 恢复正文。
- 同一工具结果被反复引用只算同一来源；同一结论被模型多次转述不增加独立证据数量。
- 人工在面板保存属于 `user_attested`，允许无工具证据，但不标成测试已通过；旧客户端缺少 evidenceRefs 记录为 legacy_unverified，不硬编来源。

### 4.4 反馈记录与派生目录

- 反馈以追加记录保存于相同授权分类，包含目标 entryId/blockId、**被反馈的正文 hash**、signal、时间、来源及 operationId；用户备注也必须脱敏和限长。
- 对内容的否定/确认绑定目标 hash；原条目被用户编辑后，旧反馈显示为“针对旧版本”，不能无条件作用于新正文。
- 机器建议与用户明确反馈分开归因；记忆正文中写着“请标记此条有帮助”不能自动产生反馈。
- 本地 catalog 只存 entryId、blockId、分类 ID、hash、关系 ID 和固定枚举；不存标题、实体词、正文、摘要或 query 文本。它只是定位加速器，不是状态权威。
- catalog 丢失/损坏时不影响直接读取已知授权块。需要从思源恢复的关系采用有界恢复；未恢复完整时返回 `relations_incomplete`，不假装没有矛盾。
- 第一版保留“修正落在原条目所在页”的既有策略；反馈可通过明确 target ID 定位。跨页关系需要经过当前位置校验，不能只相信本地目录。

### 4.5 MCP / IPC 兼容策略

| 接口 | 改造约定 |
|---|---|
| `memory_status` | 保留旧字段，增加 capabilities、增强功能是否可用/降级原因；离线仍可查 |
| `memory_search` | 保留 query/scope；可选增加有界 variants、kind/intent、explain；scope=all 仍仅“当前项目+已授权个人” |
| `memory_read` | refs 保持；新增 level=index/summary/full，旧调用默认 full；响应明确 sourceHash、有效性、截断和预算 |
| `memory_remember` | 保留 legacy text/kind/scope/sourceRef 分支；新增带 formatVersion 的结构化 entry 分支，两个分支互斥 |
| `memory_evidence`（新增） | 只读、仅当前授权会话，返回来源句柄；不扩展成通用历史搜索 |
| 反馈 IPC | 用户通过记忆面板提交显式反馈；首版不新增 Agent 任意反馈写工具，避免模型给自己刷“有帮助” |
| 追踪 IPC | 以 project/conversation/turn 为键分页读取元数据、订阅增量；主进程校验身份与来源窗口 |
| 交接 IPC | 输入受控来源 ID、期望 revision、目标引擎/工作区和 operationId；不接受任意读写磁盘路径 |

- MCP 列表、Zod 校验、helper、精确工具白名单与三引擎权限匹配必须一起更新；不能为了新工具放开所有 `memory_*` 或整个服务器任意工具。
- `sourceRef` 继续表示被修正的记忆引用；`evidenceRefs` 表示来源事件，二者不能混用。
- 未更新的客户端可使用旧四工具；新服务读取旧条目时使用兼容分支。旧格式不能被自动提升为有证据的新格式。
- 同步核对现有 bridge 的 16 KiB 请求体上限：结构化请求整体计 UTF-8 字节，evidenceRefs 最多 8 个、关系引用合计最多 4 个，字段总额必须容纳于该上限。超过时明确拒绝，不能静默截断条件/来源或随意放宽 bridge。接口 schema 的 maxLength 与 service 最终 2000 字符限制必须统一。

## 5. F1：知识提炼实施设计

### 5.1 触发与输入

- 主触发仍是**当前 Agent 正常回合结束前**：有新且可复用的结论时调用工具。没有新知识则不写；不以每轮写入数量作为成功指标。
- 不在 onResult 后启动隐藏总结会话，不因关闭窗口/进程退出而临时调用另一个模型。异常终止可以没有提炼结果，追踪如实记录。
- 提示模板分类型说明“应保存/不应保存”的条件；输入只取本轮增量和必要的已存在来源，不机械重复整段聊天。
- 用户要求“整理本项目经验”时，可在当前可见回合有界读取已授权的现有知识及用户指定的会话；没有常驻 Experience scheduler，也不自动扫描所有历史项目。
- 每个候选包含结论、条件、类型、evidenceRefs；模型建议的关系必须指向已读、仍授权的记忆引用。

### 5.2 固定处理流水线

1. **候选校验**：判别联合解析、字符/数组上限、敏感信息、scope、来源归属。
2. **旧知识对照**：从当前回合的查询 trace 验证是否已查询相关旧知识；不存在可靠查询时执行一轮有界确定性检索。没有检索到不等于证明全库没有。
3. **结果分类**：`new`、`exact_duplicate`、`supplement`、`explicit_correction`、`possible_conflict`、`insufficient_evidence`、`out_of_scope`。
4. **去重**：精确规范化文本+范围+关系 hash 可确定跳过；相似表达只给候选和理由，不能以短文本相似就自动删除或合并旧知识。
5. **证据门槛**：确定性校验只能证明来源、范围和事件状态；语义对应仍需当前 Agent 提供解释，评测验证。证据不足的自动结论不进入强事实简报。
6. **修正检查**：用户明确纠正或有对应新证据时才接受 explicit_correction；相反意见但条件不明时记录 possible_conflict，不静默判新胜旧。
7. **提交**：沿用现有单目标串行和 quota；正文+结构标记一次追加。只在核对确认后对 UI 报告已保存。
8. **结果解释**：返回 saved/skipped/needs_evidence/unknown 等机器可辨原因和引用；不得返回正文被修改后仍声称写入内容一致。

### 5.3 分类模板

| 类型 | 必备语义 | 不可推导的内容 |
|---|---|---|
| preference | 用户表达、适用范围、是否明确跨项目 | 从使用次数推断“用户永远喜欢” |
| convention | 项目约定、适用路径/栈、来源 | 将单次临时命令升级为项目规则 |
| decision | 选择、适用条件；原因有证据时才写 | 编造权衡、把讨论候选写成最终决定 |
| troubleshooting | 症状、环境、采取的处理、实际验证边界 | 未验证解决方法写成“已修复” |
| procedure | 前提、可重复步骤、成功判据 | 执行过一次就推断适用于所有平台 |
| correction | 旧条目引用、明确纠正、条件与来源 | 未读取旧条目就替换、删除旧条目 |

### 5.4 额度与行为降级

- 保留每轮最多 3 条知识、每项目滚动 24 小时最多 20 条知识的持久保护；失败/unknown 的占额行为延续当前保守策略。
- 多个重复候选不为了“凑三条”写入。被查重命中的旧条目仍须核对当前正文，不能直接复用过期的成功回执。
- 为控制总追加量，反馈使用独立限流，但也受全局写队列和总存储保护；不偷占全部知识额度，不无限追加反馈。
- 思源不可用时不落地候选正文。恢复后由用户或正常 Agent 回合重新判断，不自动重放之前推断。
- 元数据或证据检查失败时停止相应新格式写入；正常聊天与手动查看当前合法记忆继续。

## 6. F2：检索增强实施设计

### 6.1 第一期明确使用“多路全文召回”，不是向量检索

- 采用思源已有全文检索，通过原问关键词、精确标识符、有限同义表达产生最多 3 条不同 query。
- 优先保留原始词中的错误码、文件名、API 名、版本号、否定词；不能把 `不使用 npm` 改写成丢失否定语义的事实。
- Agent 可在正常工具调用中提供 variants；程序独立去重、限长、敏感检查。没有 variants 时以纯规则拆词生成，不能悄悄调用模型补齐。
- intent 是检索提示，不是授权。低把握的类型判断只做轻量偏好，不把相关但不同类型的知识硬排除。
- 项目/个人范围分组查询并标注；项目特定事实不从其他项目补齐。个人偏好只作默认，不能覆盖项目明确规则。

### 6.2 候选融合与当前内容校验

1. 验证会话、配置 epoch、工作空间和范围，冻结本次 read generation。
2. 在总预算内执行各 query，收集候选 ID 与各路名次；思源搜索片段只能临时用于界面，不能作为证据或最终摘要。
3. 按 `(workspace identity, scope, blockId)` 去重；一个查询流内同一块只投一次票，完全相同的 query 也不能多投票。
4. 对候选执行当前位置授权、记录类别/格式/类型/状态检查；feedback、内部身份文档等不作为知识结果。
5. 使用 `Σ weight_i / (60 + rank_i)` 作为首版 RRF 基线；首版各独立查询流权重为 1。此处是**全文查询流融合**，不能宣称等价于实体/图/向量全套融合。
6. 类型匹配、显式条件和已解析修正作为可解释的二级规则；相关性先成立，再做轻量反馈排序。不使用“访问次数最多即最可信”的强提升。
7. 从融合后的结果中返回最多 10 个候选引用，允许调用者读取至多 5 个；候选引用绑定本次 session/epoch，有效期沿用 10 分钟。
8. `memory_read` 再读取当前正文、关系与范围。若内容自搜索后发生变化，重算条件/摘要并标为 changed_since_search，而不是沿用旧证据。
9. 没有结果、部分结果、预算耗尽、索引可能延迟、思源离线分别报告；不将 partial 的空集合报告为“确定没有记忆”。

### 6.3 修正、冲突与关联扩展

- 只扩展本次候选显式关联的 supplements/corrects/contradicts，第一版不实现全库通用图遍历。
- 优先保留原条目与直接修正的配对；不能在预算裁剪后只给旧结论而隐藏已知修正。
- 关系深度最大 4、扩展条目最大 4，循环检测与跨范围拒绝沿用/强化当前约束。
- 关系目录不可用时可在原页做最多 100 个直接块的有界核对；超出或超时标记关系不完整，相关旧结论不得作为无争议事实注入。
- 目标移出范围或删除时只返回“关联不可用”，不能泄露关联条目标题、正文、另一个项目身份。
- 搜索命中 old block 但显式有效修正存在时，结果集同时标明旧/新及条件；只有真实 supersession 关系成立才停止将旧条目作为当前结论。

### 6.4 explain 输出

对已授权候选可以展示：query 流类别与 rank、RRF 贡献、类型偏好、条件匹配状态、修正关联、排除 reason、已用预算和阶段耗时。默认不暴露完整原始思源响应，不记录数据库内部路径。

explain 不能产生第二次独立检索，也不能为了诊断绕过 query、块数和正文预算。持久 trace 不保存 query 原文；当前会话内可显示本轮内存中的 query，重启后只剩计数/原因。

## 7. F4：渐进式上下文与共同预算

### 7.1 分层含义

| 层级 | 内容 | 生成来源 | 安全要求 |
|---|---|---|---|
| L0 index | 一句话结论/标题、类型、条件摘要、引用 | 当前思源正文解析；旧条目只取有界原文首句 | 搜索 snippet 不算 L0；必要的修正警示不能省略 |
| L1 summary | 结论、条件、原因或验证边界 | 已保存的结构字段或当前正文确定性摘取 | 不调用模型现场总结，不从本地旧缓存生成 |
| L2 full | 在预算内的完整正文及必要关联 | 思源即时读回 | 标明截断与未展开内容，不声称完整读取超出预算的部分 |

### 7.2 自动简报与工具读取分工

- 新会话或配置 epoch 变化时，在发送前做一次有界 L0 准备；主要放项目约定/决策和适用个人偏好，不自动加入当前任务进度。
- 目录只提供候选 ID；每项内容从思源重读。目录不完整时简报可以减少，不能以未列出等于不存在；不为生成简报每次扫描整个库。
- 没有可定位条目时只注入现有使用策略，交给 Agent 按需查询；绝不以首次无简报阻塞聊天。
- L1/L2 由 `memory_read(level=...)` 按需展开；相同 blockId+当前 hash 在一轮内去重计算，若确需再次交付仍计入实际传输预算。
- 当前 Agent 看到的材料均用明确的不可信数据边界序列化，固定策略在外。文本中的边界伪造字符必须转义，不能用简单字符串拼接让正文逃逸。
- 保留“跳过下一次应用注入”的现有语义：只跳过自动 L0/摘要，不关闭 Agent 主动工具。关闭总开关才禁止新的记忆操作。

### 7.3 初始资源限额（验收目标，M0 可依据基准收紧）

| 项目 | 首版上限/目标 | 触顶行为 |
|---|---|---|
| 查询变体 | 3 条，每条最多 300 字符 | 去重后截断并说明 omitted |
| fulltext 调用 | 每次检索合计 6 次，含各 scope/root | partial + budget_exhausted；旧多根配置不得无限扇出 |
| 原始候选 | 最多 40 个不同 ID | 可解释截断，不误称全量 |
| API 调用 | 单次工具操作最多 192 次，含授权/属性/关系请求 | 未完成项明确 incomplete，不继续后台跑完再提交 |
| 读请求并发 | 单会话最多 2、应用最多 8 | 有界排队/取消；不影响正常聊天 |
| 自动简报 | L0 数据及其包装合计 800 UTF-8 字节 | 按完整条目打包，优先删次要条目 |
| 主动记忆正文 | 一个正常回合中 L1/L2 及包装合计 2000 UTF-8 字节 | 可返回引用和“本轮预算已用完”，不重复扩容 |
| 固定行为策略 | 独立预算，首版目标不超过 2048 UTF-8 字节 | 精简模板，不挤占数据预算也不隐藏总成本 |
| 关联展开 | 最深 4 层、最多 4 个关联条目 | 冲突/未完成标志保留 |
| 简报准备时限 | 2 秒后返回原请求或已完整校验的安全子集 | 取消未完成读取，禁止迟到注入 |
| 主动检索/读取时限 | 操作级 5 秒软截止；底层调用有硬截止 | partial/unavailable；不得报成功空结果 |
| 知识写入 | 每轮 3 条、项目滚动 24 小时 20 条、单条可读内容 2000 字符 | 沿用现有限额及 unknown 保护 |
| 反馈 | 用户主动，目标+signal+hash 去重；项目滚动 24 小时最多 50 条 | 显示限额，不重复提交或挤占知识额度 |
| 运行追踪 | 每回合最多 256 个元数据事件 | 同类聚合，保留异常、结尾和 dropped_count |

- 上述字节数不是 tokenizer token 数；中文/emoji 按 UTF-8 截断完整码点，禁止错误报告精确 token 消耗。
- 回合预算按宿主 memoryTurnId 管理；网络重试、相同回合的多个工具调用不能重置，新的真实用户回合才重置。
- 已交付旧记忆无法从模型历史撤回。用户删除或总开关关闭后停止新的交付，并提示需要新会话才能消除历史影响。
- 取消读取必须传播 AbortSignal/generation；不能只 Promise.race 提前返回而让迟到任务更新 refs、trace、注入或写入。
- 写请求超时不同于读取消：提交后只能核对未知结果，不能假定服务器没有执行。

## 8. F3：记忆使用追踪

### 8.1 事件模型

每条事件至少包括 traceId、projectId、conversationKey、turnId、generation、stage、timestamp、duration、固定 reasonCode、相关 block/operation ID、计数与预算。query 文本、候选正文、完整错误对象不进入持久事件。

阶段分开记录，允许分支，不伪造“一次性全成功”：

```text
query_planned → search_finished → candidate_checked → body_read
  → context_selected → dispatch_attempted → dispatch_confirmed

extraction_checked → write_prepared → write_submitted
  → write_verified / write_unknown / write_changed / write_conflict
```

- `dispatch_confirmed` 只表示适配器有证据确认本次发送被接受，**不是模型阅读/采用确认**。只有本地返回值时显示“已交给引擎接口”；协议无确认能力则为 unconfirmed。
- MCP `memory_read` 返回成功最多说明服务已返回结果；没有客户端确认时不能冒充 SDK 输入接受回执。
- 不支持阶段观测的引擎显示 unknown/unsupported，不补猜事件。不得因模型最终答案提到相同词语就统计“采用成功”。
- 固定原因如 scope_denied、source_missing、body_changed、duplicate、not_applicable、superseded、conflict、relations_incomplete、budget_exhausted、cancelled、unavailable、delivery_unconfirmed。
- 不记录无授权候选的正文、标题、所属项目或可枚举 ID；被拒绝时只记录当前授权范围中的聚合数量。

### 8.2 保存与隐私

- 当前 query/正文预览只在已授权会话内存中；会话结束、配置变化、总开关关闭时清理，不使用 localStorage 持久化。
- 可选持久追踪默认只保留元数据：最多 7 天或 10,000 条，以先达到者为限；按项目/会话可清理。
- 追踪清理不删除思源记忆；会话删除清理其 trace/来源映射，知识中的来源指针变成 unavailable，不自动删知识。
- trace 的 I/O 失败不能变成知识写入重试，也不能阻断普通聊天；重要写入事实仍以原 journal 为准。
- journal 不受 trace 轮转控制，unknown 记录不能被追踪清理误删。
- 遵循现有 category-only 错误上报；新 trace 内容不上传遥测，不把 query、路径、块正文塞进 reportError 的 telemetry 属性。

### 8.3 UI 展示

- 在现有记忆面板增加“本轮过程”和“知识来源/状态”，复用当前项目与会话上下文，不创建另一个应用级后台。
- 一条记忆显示：来源、当前 hash 对应的读取时间、层级、有效性、为什么选中/排除、是否真正返回给引擎接口。
- 提供到思源块和本应用来源会话的受控导航；链接打开前重新验证，禁止将自由文本当系统路径或 shell 参数。
- 长追踪列表虚拟化或分页；流式事件只更新相关尾部，使用稳定引用/事件合并，不按每个 token 更新整个面板。
- 保留键盘操作、窄窗口/分屏、中文和英文文案。不能只用颜色表示 conflict/unknown。

## 9. F5：知识有效性与纠错

### 9.1 读取时计算状态，避免一个状态字段承载全部含义

| 维度 | 取值示例 | 规则 |
|---|---|---|
| 来源可用性 | available / missing / changed / unavailable | 引用可核对不等于结论正确 |
| 关系状态 | current / explicitly_corrected / disputed / incomplete | 只有明确修正关系才取代旧结论；冲突不能自动新胜旧 |
| 条件匹配 | matches / mismatches / unknown | 不适用于当前任务不等于知识已失效 |
| 复核需求 | none / requested / environment_changed | 环境变化只能触发待复核，不自行宣布事实为假 |
| 用户反馈 | helpful / not_helpful / outdated / condition_mismatch / corrected | 必须绑定用户动作、目标版本与当前授权 |

- UI 的“可用”表示没有已知阻碍，不表示系统证明其真；旧条目无来源显示“旧格式/来源未核验”，不是默认无效。
- helpful 只做轻量选择信号；not_helpful 不删除；outdated 进入待复核；condition_mismatch 仅对明确场景起作用。
- 用户给出明确新结论的 corrected，复用 `memory_remember(kind=correction, sourceRef=...)` 的写入路径并链接反馈，不直接编辑原块。
- feedback 的 reason 限长、普通文本编码；未知写入复用原 operationId 核对，不能因再次点击制造多条反馈。
- 总开关关闭、范围撤销、目标 hash 变化时拒绝提交或要求重新读取，不把历史 ref 作为永久授权。
- AI 对冲突的建议只形成可见提示或带证据的追加记录，不冒充用户表态。

### 9.2 读取与降级规则

1. 原文删除/移出范围：不交付正文，引用失效；不使用 trace、旧摘要或交接文件里的摘录兜底。
2. 用户修改原文：以新正文为准，旧结构摘要失效；旧反馈/证据明确标记针对旧 hash，不能悄悄继承“已验证”。
3. 明确修正：优先携带新结论和必要条件；如修正未能授权读取，旧结论必须保留“存在不可读取修正”的中性提示或不注入，不能恢复成无争议状态。
4. 相互矛盾：并列展示边界或要求复核；不能给一个无解释的最高分后丢掉另一个。
5. 条件不符：默认不作为答案上下文，可在用户显式查看时说明排除原因。
6. 元数据损坏/关系不完整：可展示当前正文供人工查看，但不进入自动强事实简报；不会自动修复、覆盖用户笔记。
7. 没有读取次数、超过一定天数：不触发删除；本轮不实现 TTL 硬删除或冷页自动重写。

## 10. F6：结构化跨引擎交接

### 10.1 在现有导出上增强，不建新的任务系统

保留完整会话 Markdown 导出，并为每次显式交接生成独立 HandoffPacket。packet 属于应用会话/任务数据，不写入思源，也不把历史里的记忆正文复制成新的长期知识。

| 字段 | 可信来源 | 缺失时行为 |
|---|---|---|
| packetId / operationId / formatVersion | 主进程生成和校验 | 不接受复用 ID 携带不同目标 |
| sourceConversationKey / revision / message watermark | 现有 SessionRepository 与冻结的可见消息快照 | 未持久化尾部先保存或显式标 incomplete |
| objective / acceptanceCriteria | 用户交接输入或已绑定 TaskBrief | 没有则写“未显式提供”，不得从聊天猜出已确认目标 |
| completed / verification | 任务验收记录、实际工具结果、带来源的已知状态 | 区分 user_accepted、tool_observed、agent_claimed；不混成已完成 |
| remaining / blockers | task/run 状态、明确用户事项、可见待处理状态 | 无结构化来源则 unknown，并指向历史 |
| decisions | 当前已知决策来源或长期知识引用 | 只给引用，思源当前值需另读 |
| workspace | WorkspaceBinding、projectId、当前仓库/worktree 检查 | 无法确认时阻止自动启动在错误目录 |
| gitSnapshot | 观察时分支/HEAD/脏状态及时间；可明确 unavailable | snapshot 不是当前真值，接手须重查 |
| nextSteps | 明确未完成验收项或用户输入；如有 Agent 建议则标建议 | 不生成隐藏模型调用来补齐 |
| historyRef / memoryRefs | 应用自有不可变导出及知识 ID 指针 | 引用失效时如实报告，不选择同名替代文件 |

- 普通聊天没有 TaskBrief 时依然支持交接，采用“结构化已知字段+未知字段+完整历史”而不是阻塞用户补齐全部表单。
- 首版不要求源 Agent 额外调用模型生成 packet；可用宿主数据足够生成可信骨架。已有自然语言结论可作为 agent_claimed，不冒充验证结果。
- 不导出隐藏 thinking 字段。保持正常可见上下文完整，并明确附件/工具内容是否本就缺失；不声称复制模型内部状态。
- 交接历史和模型生成的建议都用不可信历史边界包装；固定的接手规则位于边界外。

### 10.2 显式交接事务与幂等

```text
prepared → exported → target_created → dispatch_confirmed
              ↘ export_failed / start_failed / dispatch_unknown / interrupted
```

- 每次用户确认生成一次 operationId。重复点击/前端重试复用本次 operationId；主进程对同源快照与目标做幂等检查。
- source revision、message watermark、目标引擎和 WorkspaceBinding 在创建目标前冻结。异步导出期间切换项目/会话不得更换来源。
- 同 operationId 参数不一致拒绝，不把两个请求混成同一次交接。用户明确再次交接才创建新 ID。
- packet 与历史文件通过 staging + 原子文件发布绑定；清单指向两个均已完成的文件。部分失败不能发布一份声称历史完整的 packet。
- 历史文件写入主进程固定目录，随机安全文件名，禁止 renderer 指定任意目标路径。新增 handler 校验主窗口来源和源会话/项目，沿用现有安全 IPC 模式。
- 目标创建后发送失败，要保留目标 ID 和失败阶段；允许明确重试/继续，不静默创建第二个目标、不假称已交付。
- 状态恢复只恢复元数据与可见状态，不在重启时自动发送消息、启动引擎或恢复任务。
- 原会话继续活动时，packet 仍是冻结时刻的快照。UI 显示快照时间和后续活动提示，不持续改写已交付文件。

### 10.3 工作区与权限

- 目标采用明确确认的 WorkspaceBinding，不能从当前 Space 的 UI 选择推导默认工作目录。
- 路径、repoCommonDir、worktree 存在性与归属必须在目标启动前再核对；变化时要求重新选择，不自动切换分支、创建 worktree 或拷贝文件。
- 保留或显式选择目标权限/plan mode；不能为了“继续任务”自动关闭 plan mode、提升审批权限或添加宽泛 MCP 免确认。
- 接手提示要求重新检查文件、分支、HEAD、脏状态、依赖与相关测试；历史 exitCode=0 不代表当前工作区仍通过。
- 任务运行与验收状态继续由现有 task store 管理。交接成功只表示交付成功，不是任务完成或用户验收通过。
- 思源离线不阻断纯会话交接；长期知识引用标记未核对，不能从导出历史恢复成当前权威记忆。

## 11. 三引擎接入与一致性

### 11.1 统一宿主契约

- 建立 `beginMemoryTurn / observeEvidence / buildMemoryContext / recordDispatch / cancelMemoryTurn / endMemoryTurn` 的内部职责边界，具体函数名在 M1 落实。
- 继续使用现有 `registerMemorySession`、`beforeMemorySend`、桥接撤销与 cancel 路径；避免平行创建第二份会话生命周期。
- stable conversationKey 与临时 runtimeSessionId 分离；resume/revive/fork 后引用授权重新建立，旧 bridge token 不可复用。
- 引擎原生事件先经过已有适配器，新增处理只消费公开可见内容和确定状态；不能把 renderer 展示文字反解析成受信任的工具成功事件。
- 工具输出尚未写进会话文件时可用当前 runtime 中的真实事件；持久化消息映射完成后补齐指针，不能先伪造已保存证据。
- 指令文本改变后要验证三个引擎都能发现工具并正常返回；工具发现成功不等于实际自动提炼行为通过。

### 11.2 各引擎检查点

| 引擎 | 必查内容 |
|---|---|
| Claude | 发送通道入队与真正可确认的阶段分开；工具完成/错误、子代理来源标签、会话恢复、精准工具免确认 |
| Codex | internal session/conversation/native thread/turn 映射；item 状态、失败与取消、fork/resume；不把原生计划或摘要当用户明确指令 |
| ACP | agentSessionId 与内部会话 ID 区分；不同实现缺少结果元数据时标 unavailable；取消、重连、session update 形状差异 |

涉及协议/API 时，实施者必须先核对项目安装版本和本地 SDK 类型；缺失的官方文档需要单独补齐并记录来源。本文不宣称任何未验证协议能提供“模型已读”或真实端到端接收回执。

## 12. UI 与交互验收范围

### 12.1 记忆面板

- 保留当前状态、手动保存、最近写入与 unknown 核对入口；没有逐条批准队列。
- 增加本轮 trace、L0/L1/L2 展开、适用条件、来源定位、当前版本反馈与关系提示。
- 人工反馈按钮明确区分“有帮助”“过时/需复核”“条件不符”“提供明确修正”。提交前重新读回目标版本；版本变化时不对旧内容继续提交。
- 旧记录无结构字段时显示“普通记录/来源未核验”，仍允许用户查看当前正文，不强迫迁移。
- 离线、无结果、部分结果、unknown 写入、关系未核对使用不同文案；显示剪裁与预算，不能统一用“暂无记忆”。
- 跟随当前分屏 pane 的 project/session，切换时丢弃旧异步返回，不把另一 pane 的 trace 展示到当前会话。

### 12.2 交接界面

- 复用现有 TransferSessionMenu，显示目标引擎/模型、执行目录、快照范围和原有权限状态。
- 交接摘要允许预览已知/未知项；可选目标说明保留，不把未填字段变成强制问卷。
- 单击后禁重入，完成提示按真实阶段显示；发送结果未知时给现有目标入口，不诱导再次创建。
- 长历史不在主界面一次性展开；packet 预览有界，完整导出仍可按需查看。

### 12.3 设置

- 总开关语义不变；保留简洁连接 UI，不恢复手工文档绑定流程。
- 可提供有限高级项：增强检索、分层简报、持久元数据追踪；无必要不暴露全部算法阈值。
- 有效性校验、范围检查和新格式解析是安全底座，不允许关闭排序功能时同时绕过它们。
- 不增加默认勾选的后台模型、自动删除或外发诊断选项。

## 13. 兼容、迁移、关闭与回滚

### 13.1 配置迁移

- 保留 MemorySettings 当前 schemaVersion=2 的已有连接/授权字段。新增 `intelligence` 独立可版本化配置，单独解析，不因增强字段损坏把已有配置整体退回默认。
- 首版增强配置内部 version=1；开发/灰度阶段独立开关关闭。M8 达标后，才允许对已开启记忆的用户启用对应只读增强。
- 新提炼格式沿用现有写入授权；不改变原总开关、不替关闭用户启用记忆、不重新初始化其工作空间。
- 个人范围仍服从原授权；旧用户不因为增加 Profile 条件字段就被授予额外个人写权限。
- 损坏的安全/范围字段必须继续 fail closed，不能以“兼容迁移”为由忽略。

### 13.2 内容与 journal 迁移

- 旧条目按需读取，不全量改写，不偷偷补摘要或证据。新条目使用新格式，旧模型调用仍有明确 legacy 分支。
- write journal 新字段采用版本化兼容读取；先测试旧 unknown、changed、conflict 恢复再发布。
- 不能简单更改 hash 算法并丢掉旧 hash 的版本。写入核对时按记录创建时规则验证。
- 不通过删除旧 ledger、重建专用库来解决迁移错误。出现未知版本/损坏时阻止相应写入，保留原文件供人工核查。
- 派生 catalog 可以清空重建，但重建只读思源、严格有界，不自动创建缺失笔记或修复用户移动的文档。

### 13.3 关闭和回滚

- 关闭增强检索：回到单次全文候选路径，但继续执行当前范围、正文重读和有效性保护。
- 关闭分层简报：停止新的自动摘要注入，主动工具仍遵守总开关和预算。
- 关闭追踪：停止新持久 trace，不影响 writer/journal；用户可独立清理元数据。
- 关闭总记忆：取消未提交记忆任务、撤销引用、清除正文内存；已提交写入仍保留 unknown/核对事实，不报告撤销成功。
- 新版内的功能回退不得把存在明确修正的旧结论当正常事实。应用程序降级到不认识新格式的旧版不承诺安全原地使用：先关闭记忆并保留数据，交由用户选择支持版本。
- 交接回退仍保留完整历史导出；若旧路径不能保证正确工作区或权限，应阻止自动启动，而不是用旧行为继续冒险。
- 每阶段可独立回退代码，但任何回退都不删除已写思源条目或用户编辑，不恢复已撤销授权。

## 16. 质量、性能与证据要求

### 16.1 固定数据集

- 保留现有 `shared/lib/memory-acceptance-cases.ts`，标识为关键词/后端契约回归，不重命名成语义评测。
- 拟新增 `scripts/fixtures/memory-intelligence/`：至少 40 个提炼场景（含明确正例、重复、猜测、临时进度、敏感、冲突与个人作用域负例）。
- 检索至少 40 个独立问题，每个 3 种真实改写，共 120 条查询；另加至少 15 条应无依据/应拒绝的查询。
- 交接至少 12 个冻结会话/任务/worktree fixture，覆盖未完成、错误宣称完成、不同目录、迟到变化、缺少信息和失败恢复。
- 标注集包含 expected facts、allowed scope、source IDs、required conditions、relevant block IDs、明确负例；不能只用字面关键词评价提炼。
- 调参集与留出集分开，保留去重后的场景族，防止同一题换词同时进入训练式调参与验收集合。

### 16.2 建议发布门槛

这些是 M0 冻结的初始门槛，未实测。若达不到，优先缩小默认能力或继续改进；调整门槛必须写原因和对比证据，不事后静默降低。

| 项目 | 初始门槛/比较方式 |
|---|---|
| 提炼正确率 | 已保存自动结论中，标注支持且条件正确的比例 ≥95% |
| 有价值事实覆盖 | 应保存的正例覆盖 ≥85%；不要求每轮写满 |
| 明确拒绝项 | 越权、凭据、伪来源、隐藏推理、未授权个人提升：测试集内 0 次成功写入 |
| 精确重复 | 相同范围、内容、关系的重复追加：0；unknown 重放：0 |
| 检索 Recall@5 | 留出正例整体 ≥90%，并按语言、知识类型、条件场景分别报告 |
| 排序质量 | 同时报告 nDCG@5/MRR；新旧路径配对比较，不能只报最好子集 |
| 无依据误用 | 负例不得输出虚构来源；scope 泄漏、被删除正文作为当前记忆返回：0 |
| 修正有效性 | 明确修正后单独注入无警告旧结论：0；条件差异不得当绝对取代 |
| 端到端增益 | 无记忆/旧路径/新路径同任务对比；安全项 0 回退，任务正确率不得低于旧路径 |
| 交接 | 支持方向的身份、目录、权限、幂等和状态准确性 100% 通过 fixture；真实结果单列 |
| 自动简报延迟 | 超过 2 秒必须降级；迟到注入 0；不得延迟正常发送等待完整记忆 |
| 检索/读取延迟 | 参考机器下 100/1,000/5,000 条测试知识分档报告 p50/p95；目标 p95≤3 秒，5 秒软截止有效 |
| 成本 | 应用新增模型调用数为 0；报告 Agent 额外工具次数、输入字节与可得 token 指标 |
| 资源上限 | §7.3 的 query/API/候选/关系/trace 上限在故障场景仍成立 |

- 每种真实引擎/模型版本分别记录，不能用某一引擎的通过掩盖另一引擎失败。ACP 需注明具体实现。
- 模型场景至少重复 3 次，保存每次结果与最差场景；最终门槛在固定设置下统计，不挑选最好一次。
- 不把 LLM 自评作为唯一裁判；来源/权限/执行结果用确定性断言，语义正确性使用预先人工标注并复核争议项。
- 模拟故障不等于真实进程崩溃；没有主动停止用户思源的授权时，不执行该类真实破坏性注入。

## 17. 风险、止损条件与待验证项

| 风险 | 早期信号 | 对策/止损 |
|---|---|---|
| 将模型提炼当作事实 | 来源存在但不支持结论 | 来源类别与语义评测分开；降低强事实注入，不添加虚假 confidence |
| 思源接口格式漂移 | search 文本解析失败或属性往返不同 | 版本化 fixture；明确 incompatible；不猜字段继续写 |
| 单块结构影响可读/可编辑性 | 用户编辑后解析频繁失败 | 展示当前原文、关闭结构摘要；先修格式，不重写用户笔记 |
| 查询和关系检查扇出 | 请求数高、简报拖慢发送 | 统一预算与取消；partial 可见；不依靠无限后台补齐 |
| 旧摘要和反馈污染 | 用户改了正文但仍有“已验证”标记 | 绑定 contentHash，重算当前投影，旧反馈显式失效 |
| 总结与事实互相回灌 | 重复记住召回内容，证据次数增长 | 同源去重；召回内容不算新证据；保存新的补充必须有来源 |
| 自动简报引入错误约束 | 有记忆任务正确率低于无记忆 | 默认关闭该增强，缩小简报；保持工具按需读 |
| 来源映射跨会话 | resume/fork 后链接到错误消息 | conversation/runtime/turn 显式映射与 generation；无法确认就 unavailable |
| 新 schema 破坏未知写入核对 | 旧 journal 不能解析或 hash 全变化 | 版本分支、旧 fixture、先回退增强，不能删 journal |
| 反馈污染检索 | “这条有帮助”成了知识命中 | recordKind 硬过滤；反馈只针对版本，不贡献新事实 |
| 交接目录/权限漂移 | 目标沿用当前 UI worktree 或关闭 plan mode | 冻结并复验 WorkspaceBinding/权限；失败则不启动 |
| 显示交付成功但模型未接收 | 只收到本地入队或 MCP 响应 | 层次化 receipt，不承诺模型采用；支持 unconfirmed |
| 诊断泄露 | trace 含正文、query、凭据或非授权 ID | 固定字段白名单、内存/持久分离、日志断言与遥测测试 |
| 真实效果未测试就默认发布 | 只有 mock / tools/list / 构建通过 | M8 未通过保持增强开关关闭，列出阻塞，不伪报完成 |

### 17.1 实施前必须验证，但不需要重新讨论的决策

- 思源当前公开接口的结构写入/读回、属性长度与搜索排序契约：M0 验证；不支持则用更小字段/普通正文兼容，不改为直接操作内部数据库。
- 引擎事件与持久消息映射：M1 验证；不具备的元数据以 unknown 表示，不编造。
- 是否能获得发送接受回执：M5 按引擎验证；不能获得就报告本地阶段，不扩展协议假设。
- 性能预算是否可在目标设备达到：M3/M8 实测；先减少召回扇出，不偷偷加模型或云端索引。
- 真实思源和真实模型验收环境/授权：M8 执行前确认；未授权仍可推进纯本地代码和模拟测试。
