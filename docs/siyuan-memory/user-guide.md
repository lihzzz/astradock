# 思源长期记忆使用说明

## 一个固定的大脑

所有新记忆都存储在本机思源的 **AstraDock 记忆** 专用笔记本中。切换项目、会话或模型不会切换记忆库。应用自动维护身份、分类和写入分页，不需要文档 ID、摘要块 ID、读取范围或项目绑定。

## 首次启用

1. 启动本机思源。
2. 打开 AstraDock 的“设置 → 长期记忆”，打开开关或点击“连接并启用”。
3. 应用自动探测本机连接，创建或复用带有应用身份标记的专用库，然后显示“长期记忆已就绪”。
4. 只有思源地址不是默认地址或需要认证时，才展开“连接设置”。默认地址为 http://127.0.0.1:6806，只支持本机 HTTP，不允许远程地址或跳转。
5. Token 留空会保留已有凭据；明确点击“清除 Token”才清除。安全存储不可用时 Token 仅保留在本次进程，不明文落盘。

开关授权助手自动保存有依据的项目结论与明确的跨项目偏好，不逐条询问。关闭后停止记忆读写，但不删除思源内容。“查看记忆”在思源打开固定记忆库。

## 自动分类与边界

- 当前项目的约定、决策、排障和流程自动归入该项目分类。
- 明确的跨项目偏好存入通用分类；不能把仅适用于一个项目的约定升级成全局偏好。
- 默认检索当前项目优先、通用偏好其次，不混入其他项目的约定。
- 只授权专用库中的对应分类，不读取其他笔记本正文。
- 分类路径和内部身份由应用维护。请勿删除内部身份标记或移动自动管理文档；发生变化时应用停止访问，不猜测替代目标。

## 重新连接与升级

“重新连接”核对原库，不等于新建空库。思源切换工作空间、原库关闭/删除、身份记录损坏时会提示并停止访问，请恢复原工作空间或原文档。

初始化失败或响应丢失时，应用持久保存创建意图和所有权标记。再次连接先核对已创建的对象，不盲目重复创建；无法确认的操作保留待核对状态。

旧版手动绑定不会被自动搬迁、改写或删除。点击“连接并启用”后，新记忆进入专用库；旧笔记保留在原位置，不自动纳入新库的检索范围。仅改版界面不会自动开启此前关闭的记忆。

## 自动记忆

当前 Agent 在最终答复前判断是否有新知识：明确偏好、项目约定、已确定决策、已验证排障、成功流程或明确修正。先搜索避免重复，再调用 memory_remember 直接保存；不调用额外总结模型。模型行为不是每次必然写入的保证，不应期待每轮创建条目。

- 精确相同内容复用已有操作，核对当前结果，不盲目追加。
- 分类内自动分页：一页达到 90 个直接块后，后续新条目写入下一页；旧页仍在同一记忆库中可搜索和核对，无需用户更换绑定。单页核对保留 100 块安全上限，明确修正写回原条目所在页。
- 每轮最多 3 条；当前实现额外使用项目滚动 24 小时最多 20 条的持久保护，避免会话恢复重置限额。
- 正文上限 2000 字符；应用拒绝常见凭据模式，但规则检测不能保证识别所有敏感信息。
- 输入含 Markdown/HTML/属性等语法时按普通文本存储，不让模型注入内部操作属性。
- 也可以在面板、消息菜单或 /remember 命令手动保存。

## 召回与失效

搜索仅发现候选；最终正文每次从思源重读。思源索引可能短暂返回已删除结果，应用不会退回使用搜索摘要。

固定记忆库不要求手工配置摘要。应用提供记忆使用策略，当前 Agent 按需搜索并读取正文；读取正文合计使用 2000 UTF-8 字节的保守预算，不是精确模型 tokenizer 计数。旧版配置兼容路径仍支持原有摘要。

“跳过下一次应用注入”不关闭 Agent 主动工具；关闭全局长期记忆开关才禁止记忆操作。已经进入聊天历史的旧内容无法撤回，需要彻底消除影响时开始新会话。

思源不可用会出现一次轻量提示并显示状态；聊天继续，不启动思源，不使用离线笔记副本。

## 保存状态

- verified：写后读取确认成功。
- unknown：请求结果无法确定；点击核对只查现有结果，不重新追加。
- changed：对应操作已存在，但正文被用户修改；保留实际内容，不覆盖。
- conflict：同一操作出现多个匹配，需要人工检查，不自动删重。

应用仅保存操作 ID、目标、hash、状态等最小写入记录，不保存正文离线队列。重启后未完成操作恢复为 unknown，不自动重放。

## 旧后端清理

产品代码及依赖已切换到思源，不会自动启动旧服务。真实旧数据库、密钥未在重构过程中删除。

提供 scripts/cleanup-legacy-memory.cjs：默认只列出指定 openacpui-data 内的独占旧数据清单，不读取或输出密钥内容。

```powershell
node scripts/cleanup-legacy-memory.cjs --data-dir="C:\实际用户数据目录\openacpui-data"
```

需要实际清理时，先退出应用和旧服务、审核清单并按需归档，再明确传入 --apply --confirm=DELETE-HINDSIGHT --app-and-legacy-service-stopped。服务端口不为 8888 时还必须指定 --legacy-port。脚本拒绝目录链接/越界目标和占用端口，不删除共享 uv/Python/模型缓存，也不触碰思源数据。

应用已运行时不要执行清理；停用端口检查不是进程归属的绝对证明，操作者仍须确认旧服务已退出。数据清理后不能承诺旧版本原地恢复，回退需明确使用事先保存的归档。

## 可选智能增强（2026-10-25）

新构建提供六项增强。由于真实模型质量及真实思源新格式写入验收尚未完成，**默认关闭**；请在“设置 → 长期记忆 → 记忆智能增强（试验性）”显式开启。详细证据与未完成门槛见 [智能层实施与验收记录](intelligence-upgrade-status.md)。

### 提炼与检索

- Agent 可调用 `memory_evidence` 获取当前回合可见的宿主来源，再通过结构化 `memory_remember` 保存结论、适用条件、说明及来源。
- 新结构化内容仍是思源中可编辑的普通文本；源数据和模型生成内容都不是指令。来源会话存在不等于结论已经被证明正确。
- 检索可提供有限变体，融合多路全文结果；可以按类型筛选，并关联补充、矛盾和明确修正。这不是向量检索。
- `memory_read` 可选择 index、summary、full。增强模式下多个读取共享本轮 2000 UTF-8 字节预算；超限显示部分结果/截断，不偷偷扩大上下文。
- 自动简报单独可选，最多 800 UTF-8 字节；从思源重新读取，不使用本地正文缓存。目录不完整或条目过长时可以没有自动简报，Agent 仍可按需查询。

### 整理历史经验

在记忆面板展开“整理历史经验”，显式选择最多 3 个本项目会话，点击授权，再向当前 Agent 发送整理要求。授权只用于下一次可见回合，读取有界的可见用户/工具证据，不扫描全库、不导出隐藏推理、不启动后台总结模型。历史记录标为 recorded，不冒充当前测试结果。

### 追踪与纠错

- 面板显示本轮阶段：搜索、候选检查、正文读取、上下文提供、写入核对。发送被接口接受不等于模型一定采用。
- 具体 query 和候选 ranks 可在本轮工具调用及 explain 结果中检查；面板追踪以元数据为主。
- “有帮助”“需要复核”“条件不符”等反馈绑定实际读过的正文版本；原文被修改后应重新读取，不沿用旧反馈。
- “提供明确修正”会追加与原条目关联的新记录，不覆盖原文。存在矛盾或不可核对来源时提示复核，不自动判定最新结论正确。
- “思源中查看”只打开当前仍授权的引用。引用失效后需重新查询，不能用旧引用访问移动后的范围外笔记。
- 可选持久追踪只保留最近 7 天、最多 10,000 条过程元数据；没有查询或正文副本。ID 定位目录也不是知识备份，丢失后不以旧正文兜底。

### 跨引擎交接

选择目标引擎后，会先生成并展示冻结快照：目标、工作区、权限/计划模式、已知验收状态和需要复查的事项。确认后才创建目标会话；完整可见历史另存为不可变文件，隐藏推理不会导出。

接手代理必须重查当前目录、Git 状态、文件和必要测试。交接不自动完成任务，也不增加权限。目标已创建但发送结果不明时，应打开已有目标继续，不重复创建。思源离线不阻止纯会话交接，但不能将导出历史里的旧记忆当作当前思源正文。

交接快照/历史属于会话数据域，不是长期知识库；删除源会话不会自动擦除已经交付的独立上下文文件或目标会话历史。
