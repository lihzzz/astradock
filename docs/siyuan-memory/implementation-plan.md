## 1. 目标与不可变原则

用本机思源替换 Hindsight 作为长期记忆的存储与检索后端。思源保存权威正文，AstraDock 负责项目绑定、授权范围、上下文使用、受控追加、去重及未知写入核对。

1. 思源不可用：提醒“思源未连接，长期记忆暂时失效”；聊天继续，不自动启动思源，不使用笔记副本兜底。
2. 用户编辑笔记：以实际正文为准，搜索后重新读取最终选中的块；不能用搜索摘要替代读取失败的正文。
3. 写入超时：先核对结果；无法证明未执行时，不自动重复追加。
4. 没有云端记忆服务：该子系统只连接 loopback，不引入 embedding、reranker、专用总结模型或外部提取服务。
5. 总结复用当前 Agent，在当前工作回合中生成；不每轮机械保存 User + Assistant。
6. 项目启用并绑定写入位置后，Agent 在授权范围内直接写入；不弹逐条确认、不设待审批收件箱。
7. 默认只自动追加项目记忆，不擅自修改、删除、移动原有笔记。
8. 个人记忆读取与自动写入分别配置。未启用个人写入就不写，也不临时弹窗询问。
9. 不直接操作 .sy 文件或内部数据库；只使用已验证 MCP 与公开 HTTP API。
10. 不把本计划解读为全应用离线保证：当前会话引擎的模型运行位置属于引擎配置。记忆集成不得偷偷改变引擎，也不得新增外发路径。

## 2. 范围与非目标

### 2.1 第一版交付

- 本机连接、能力探测、工作空间校验及故障状态。
- 个人与项目的摘要、只读知识范围、指定写入文档绑定。
- 首轮精简摘要注入，Agent 按需全文检索与最新正文读取。
- 当前 Agent 自动总结、有界自动追加、精确去重、来源追踪及修正关系。
- 写入 operationId、最小 journal、未知结果核对与重启恢复。
- Claude、Codex、ACP 统一记忆工具接入。
- 轻量保存通知、读取来源、错误及冲突状态。
- 思源重构验收后完整移除 Hindsight 的代码、依赖、配置入口和构建残留；应用专属历史数据与密钥按第 14 节清理流程收尾。

### 2.2 不在第一版内

- 思源 fork、内核嵌入、自动启动、插件开发。
- 全库开放、任意 SQL、semantic 检索、向量索引。
- 自动读取附件、抓取外链、执行笔记嵌入、无限递归引用。
- 笔记全文同步、离线记忆副本、离线正文积压后自动补写。
- 独立后台总结模型、隐藏总结回合、每轮全文归档。
- 自动改写或删除用户笔记、自动迁移全部旧记忆。
- 严格 exactly-once 或跨外部并发修改的原子授权承诺。

## 4. 架构与代码职责

```text
Claude / Codex / ACP
  → AstraDock 会话级记忆工具 bridge
  → MemoryService（身份、范围、预算、去重、写入核对）
  → SiYuanAdapter
      ├─ MCP：能力发现、受限全文搜索、追加
      └─ 公开 HTTP API：正文、子块、属性的结构化读取
  → 用户已运行的本机思源
```

UI 保存、应用摘要注入和 Agent 工具都必须经过同一个 MemoryService。MCP 和 HTTP 只是传输实现，不得形成两套权限体系。

建议模块：

```text
electron/src/lib/memory/
  service.ts             # 统一编排
  policy.ts              # 范围、action、预算、会话权限
  bindings.ts            # 项目/个人绑定与 revision
  availability.ts        # 连接状态、错误分类、有界重连
  context.ts             # 摘要、正文预算、hash 与来源
  deduplication.ts       # 精确重复及操作复用
  write-journal.ts       # 最小操作记录与未知状态恢复
  agent-bridge.ts        # 会话级工具接入，真实 Token 留在主进程
  siyuan/
    connection.ts        # HTTP/MCP 生命周期与运行时校验
    capabilities.ts      # 实际能力契约
    search.ts            # 固定全文检索与候选解析
    blocks.ts            # 最新正文、属性、追加与核对
```

不先建设通用多后端插件框架；保留小型 typed adapter 便于测试即可。

## 5. 配置、身份与权限

### 5.1 全局配置

建议新增带 schemaVersion 的思源配置；重构期间不覆盖旧 Hindsight 数据，最终按 P8 和第 14 节完成旧配置与数据清理：

- enabled、baseUrl（仅 loopback）。
- expectedWorkspacePath、identityAnchorDocumentId。
- personalSummaryBlockIds、personalReadScopes、personalWriteDocumentId。
- personalReadEnabled、personalAutoWriteEnabled（分别控制）。
- 摘要/正文预算、超时及自动写入限额。
- Token 独立保存在主进程安全存储，不进入普通设置、renderer、日志或 Agent 环境。

安全存储不可用时，不沿用通用 store 的静默明文回退：支持无 Token 连接，或采用仅进程内 Token 并明确提示无法持久保存。具体 UX 在 P1 固定。

### 5.2 项目配置

- projectId、enabled、revision。
- summaryBlockIds。
- readScopes：notebookId、documentId、includeDescendants。
- writeDocumentId：明确且唯一的追加位置。
- includePersonalMemory。

保存 ID 而非标题；标题用于展示。操作时解析当前位置，不能把旧路径当作永久身份。修改配置递增 revision；异步返回前复查 revision。

项目启用记忆并绑定目标即允许自动追加，无逐条确认。个人写入仍需要事先启用对应全局权限，但不是每条弹窗。

### 5.3 工作空间校验

使用 endpoint + 规范化工作空间路径 + 用户选定身份锚点文档组合校验。路径变更、锚点丢失、工作空间检查失败时暂停，要求重新绑定，不自动在新位置创建同名文档。

此组合用于本机误操作防护，不是密码学身份。复制整个工作空间可能保留路径外的相同块 ID；无法强区分时明确局限，不伪造 UUID。P0 必须验证所用 API，不能依赖未经确认的内部字段。

### 5.4 访问控制

- 项目身份来自已注册会话，而非模型传入 projectId。
- Agent 不指定 endpoint、Token、任意 notebook/path、SQL、写入文档 ID。
- 所有 tool/action 白名单，禁用 SQL、semantic、文件、插件、同步和外部网络工具。
- 会话停止、项目删除、连接或绑定变化时撤销 bridge 权限和候选引用。
- 操作前与结果交付前复查权限和 revision。
- 范围过滤不等于权限：最终读取仍需归属校验。
- 只读知识可广于写入范围；自动写入只进入指定文档。
- 不通过扩大全部引擎工具权限来实现记忆免确认。

## 6. 召回与当前内容语义

### 6.1 精简摘要

新会话首轮读取指定个人偏好与项目摘要，默认约 800 tokens。恢复会话、断线恢复或用户刷新时重新读取。第一版不每轮扫描所有摘要。

重新读取后计算正文 hash。内容改变时明确新内容替代旧版本；已经进入聊天上下文的旧内容不能真正撤回。彻底消除旧内容影响需要新会话，不能承诺删块即让所有活跃模型遗忘。

### 6.2 按需全文搜索

固定 fulltext、method=0、相关度降序（本机 schema orderBy=7），明确 page/pageSize 上限。只搜索绑定范围，不因结果不足全库兜底。

项目与个人结果分别获取，按项目优先、配额、去重融合。不要仅拼接个人结果后 slice，避免挤占项目记忆；不假设跨查询 score 可直接比较。

返回候选 ID/短摘要/来源，建议对 Agent 暴露会话内短期引用。引用失效后重新搜索，不能作为永久读取授权。MCP 文本返回解析必须 fail-closed；若目标版本有已验证公开结构化搜索 API，可在 P0 决定替代，不静默调用内部接口。

### 6.3 最终正文读取

1. 校验会话、连接身份、绑定 revision。
2. 校验候选块当前所属文档、笔记本及范围。
3. 从思源重新读取当前正文。
4. 排除已删除、失效、越界块；读取错误不回退搜索摘要。
5. 去重、附上来源和读取时间、计算 hash、统一预算截断。
6. 返回前再次检查 revision 和会话是否仍有效。

不自动展开外链、引用、附件或执行 SQL 嵌入。普通用户笔记只读，不根据记忆 Markdown 重建复杂容器。无法安全提取的块类型返回不支持，不转换后写回。

默认值作为初始产品参数：摘要约 800 tokens；单次正文总预算约 2000 tokens；最多 5 个最终块；搜索每页 10 条、最多 2 页。P0 固定预算计算规则（tokenizer 或保守估算），避免虚称精确 token 上限。

## 7. 自动总结策略（无逐条确认）

### 7.1 触发时机

当前 Agent 在最终答复前检查是否产生新的长期价值：

- 用户明确说“记住”。
- 用户明确表达稳定项目约定或偏好。
- 排障已解决且有验证结果。
- 技术方案或实施决策已明确确定。
- 任务完成，形成已验证的可复用流程。
- 新证据明确修正旧结论。

无新增价值就不调用工具。不要求每个回合写一条。

### 7.2 内容类别

| 类型 | 保存内容 | 默认作用域 |
| --- | --- | --- |
| preference | 用户明确表达的偏好，不推断身份和性格 | 项目；明确跨项目且允许个人写入时为个人 |
| convention | 项目规范、包管理器、约束及适用范围 | 项目 |
| decision | 已确定结论、原因、限制 | 项目 |
| troubleshooting | 症状、确认原因、有效步骤、验证结果 | 项目 |
| procedure | 成功执行的可复用步骤及前置条件 | 项目 |
| correction | 新结论、修正原因、被修正引用 | 与被修正范围一致且当前可写 |

不保存完整对话、工具日志、中间推理、猜测、临时进度、密钥、无新增信息的复述。用户引用或转述的内容不能自动当作用户自己的偏好。

### 7.3 总结执行点

向三引擎提供同一段受限行为规则：任务完成前识别候选 → 检索已有记忆 → 总结有依据的增量内容 → 调用 memory_remember → 正常回答。

总结由当前 Agent 在当前工作回合中完成；主进程的回合完成事件只汇总状态，不在模型结束后凭空生成总结，也不另开隐藏 utility 回合。提示词不是效果保证，需引擎级行为评测；不支持的引擎明确报告限制。

### 7.4 限额

初始保护：每个完成节点/回合最多 3 条，每条正文最多 2000 Unicode 字符，单会话最多 20 条自动追加。每次工具调用只写一条；超额停止自动追加并轻量提示，不拆分绕过。逻辑会话恢复不能重置限额绕过保护；计算规则和持久化范围在 P2 固定。

### 7.5 存储格式与来源

正文尽量包含结论、适用条件、依据。机器字段由应用生成：operationId、projectId、来源逻辑会话/轮次、kind、scope、正文 hash、schemaVersion、可选修正引用。

Agent 只能提供普通文本及受限枚举，不能提交任意 IAL、DOM、SQL 嵌入或目标 ID。应用安全序列化并附加自身属性；测试换行、引号、IAL、HTML、嵌入语法和伪造属性，确保不能逃逸为额外结构或覆盖 operationId。敏感内容检测失败时拒绝/安全脱敏并报告，不误报完整保存成功。

## 8. 去重、冲突与修正

- Agent 层：保存前搜索，判断重复、增量或修正，不凭空写入。
- 应用层：规范化首尾空白/换行后计算正文 hash，结合目标及作用域检查同会话重复、进行中和未知操作。
- operationId 由主进程生成；同一次执行的内部重试复用 ID。Agent 重复调用可按会话 + 目标 + 规范化正文复用已有操作结果。
- 不粗暴删除标点、数字或所有空白，避免错误合并不同事实。
- 不引入语义模型；精确去重有确定性保障，所有同义表述去重不作承诺。
- 修正采用新条目追加，记录旧块引用；不自动删除或重写旧条目。
- 仅明确、合法的修正关系可以影响召回优先级；不能简单“最新的就对”。关系链设深度/数量上限和循环检测；越范围引用不展开，无法判定则展示冲突。
- 从旧候选出发如何发现新的修正条目必须有明确读取路径（例如限定记忆文档内元数据核对），在 P5 验证；不能假设搜索一定返回新条目。

## 9. 写入状态机与最小 journal

```text
received → policy-checked → deduplicated → prepared → submitted
                                                  ├─ verified
                                                  ├─ rejected
                                                  └─ unknown → reconciling
                                                                 ├─ verified
                                                                 ├─ conflict
                                                                 └─ unknown
```

### 9.1 提交

1. 校验会话、工作空间、绑定 revision、写入开关、限额和正文。
2. 精确去重，串行化同一目标文档的写入。
3. 持久化最小操作记录，再发请求。
4. 同次追加正文与 operationId；不把关键标记放在事后 attr.set。
5. 校验成功响应，获取 blockId，并重新读取正文及属性。
6. 核对后才显示已保存。

已知成功响应但最终读取失败，也不能直接 verified；保持可核对状态。异常 HTTP/超时/断连不是确定未执行的证明。

### 9.2 journal

记录 operationId、工作空间绑定、projectId、目标、正文 hash、状态、时间、已知 blockId；不记录 Token，不作为离线正文队列。原子持久化。存储失败时不得继续提交写入。

未知操作跨进程保留；重启把 submitted 等未完成状态转入 unknown，只核对，不自动重放。已完成记录按保留策略清理，未知记录不得静默丢弃。可先采用已完成记录保留 30 天的默认策略，在 UI 提供核对状态而非隐藏恢复。

### 9.3 核对

- 已有 blockId：直接读取并验证 operationId、目标与内容。
- 没有 blockId：枚举指定文档直接子块，分批读取属性，匹配 operationId；不用全文搜索的“无结果”推断未执行。
- 唯一匹配且正文一致：verified。
- 唯一匹配但正文被改：记录已存在但内容变化，不覆盖、不追加。
- 多匹配：conflict，不自动删重。
- 无匹配：可能仍在执行或派生状态滞后，有限核对后仍 unknown。
- 工作空间/目标变更：暂停核对，不跨工作空间继续。
- 达到文档规模/时间/响应上限：停止并说明，不能扩大全库扫描。

默认恢复操作只做核对。严格 exactly-once 无服务端唯一约束支持时不可承诺。真实执行中超时需模拟测试；此次丢弃成功响应只验证已完成写入的发现路径。

## 10. 可用性、UI 与工具契约

### 10.1 连接状态

unconfigured / connecting / ready / unavailable / auth-required / incompatible / workspace-mismatch。项目 binding-invalid 单独表示。

- 错误分类清晰：鉴权失败不等于未启动；服务故障不等于无相关记忆。
- 状态变化提示一次，避免每轮 Toast；持续状态标记可见。
- 重连有界、合并并发，不自动启动思源、不安装依赖。
- 建议初始预算：状态探测 1 秒，摘要准备总等待 2 秒；主动工具读取最多 5 秒；写入提交最多 15 秒，超时转 unknown。具体时限需真实环境测量，超时取消不等于服务端操作取消。
- 忽略连接 generation 已变化的迟到响应。

### 10.2 Agent 工具

| 工具 | 输入 | 输出/约束 |
| --- | --- | --- |
| memory_status | 无 | 当前会话可用性、范围摘要，不暴露秘密 |
| memory_search | query、scope | 有界候选；主进程注入真实范围 |
| memory_read | 会话内候选引用 | 当前正文、来源、hash、读取时间 |
| memory_remember | 普通正文、kind、scope、可选合法修正引用 | verified / duplicate / unknown / rejected 等结构化状态，不逐条确认 |

工具名字为设计契约，最终应保持三引擎一致。所有状态通过 typed union + 运行时 schema 表达，不能用 HTTP 200 代替业务成功。

### 10.3 界面

- 设置：地址、可选 Token、能力测试、版本、工作空间、个人读写权限。
- 项目：开关、摘要块、只读文档、唯一写入文档、个人记忆使用设置。
- 会话：应用注入快照、Agent 读取记录、来源、保存结果、未知/冲突核对入口。
- “跳过下一次应用注入”只跳过自动注入，不宣称关闭 Agent 工具；项目关闭才禁止全部记忆操作。
- verified 轻量提示“已保存项目记忆”；不弹审批框。
- UI 展示是当次读取/写入记录，不是新的权威笔记缓存。

质量样本建议至少 20 个中文/中英混合问题，覆盖约定、决策、排障、同名跨项目、无答案、同义表达、新旧冲突。建议首版门槛：明确关键词样本的相关候选 Recall@5 >= 80%；至少 20 个应写/不应写行为样本，内容策略正确率 >= 90%。作用域越权、敏感凭据保存、未知状态伪报成功必须为 0。先固定样本与口径，再测评；同义表达单独报告，不用改变题目美化结果。未达标要记录并决定改善或收窄能力。

性能在固定测试集/文档规模上报告 p50/p95，不能仅报单次成功。初始目标为自动摘要超过 2 秒就降级发送原消息；其它工具按各自有界预算返回错误或 unknown。枚举核对的规模上限须在 P0/P4 实测固定，超过上限明确暂停，不在后台无限执行。

## 14. 升级、完整删除与回退边界

### 14.1 顺序与完成定义

1. 先完成思源重构及验收，再撤销旧会话工具并停止本应用拥有的旧 Hindsight 实例。
2. 移除旧源码、依赖、配置、工具入口、专属构建资源和测试，不保留可选旧后端或故障自动回退。
3. 清查应用独占的旧数据、profile、密钥及配置，按确认的处置范围清理。
4. 从干净输出目录构建并审计；记录实际清理结果和例外。

“完整删除”包含产品实现与本机专属遗留处置，不是仅把 enabled 设为 false。历史文档可以提及旧设计，但必须明确已退役；一次性升级清理代码仅允许删除/迁移旧状态，不能启动或调用旧服务。

### 14.2 数据、凭据与路径安全

清理候选包括当前用户数据根目录中的 hindsight 子目录、旧 memory-secrets/hindsight 记录、Hindsight 专属项目配置及专属安装/输出文件。实际路径必须从旧实现和当前 profile 解析，不能假定所有安装位置相同，也不能按名称搜索后直接批量删除。

- 执行前生成精确绝对路径清单，核对归属、体积、是否有未完成旧写入、是否被进程使用。
- 历史记忆是用户数据。默认产品升级不能因本项目计划而对所有用户自动销毁；本机实际删除前展示清单并确认一次“删除或导出归档”的选择。此确认只针对不可逆旧数据清理，不是每条新记忆写入确认。
- 如用户选择导出/归档，先验证可读取、路径与数量清单，再删除运行目录；归档与运行目录分开，应用不得继续读取归档。不要把密钥默认复制进归档。
- 删除旧密钥包括专属安全存储记录和专属 profile 临时明文残留，不触碰其他模型、MCP 或思源 Token。
- 删除目录前解析真实路径并拒绝越出预期 profile 的目录联接/符号链接。不得删除 Harnss/openacpui-data 根目录或思源工作空间。
- 共享 uv、uvx、Python、Hugging Face 缓存、pnpm store 不属于 Hindsight 专属数据，不能整目录清空。无法证明独占的缓存记录为共享豁免，不为追求零字符串残留破坏其他工具。
- 只停止精确识别的应用自管 Hindsight 实例，不按进程名全局杀进程。
- 清理可重入、记录完成步骤；中断时报告未完成路径，不将部分清理标记为全部完成。重试前重新校验真实路径及归属。

### 14.3 配置迁移与回退

- 思源配置使用版本化命名空间；旧 enabled 不自动授予新工作空间写入权。
- 迁移后删除旧运行配置字段，仅保留必要的升级版本/清理状态。旧设置重复载入不能重启旧服务。
- 新版本故障时关闭思源记忆、正常继续聊天，不静默回退 Hindsight。
- 代码回退通过版本控制/旧版本安装完成；清理后无法承诺旧数据原地可用。若需要恢复，只能按用户明确选择的归档恢复流程执行，不为回退永久保留旧后端。
- 如需导入历史记忆，必须在删除前单独选择导出/导入，不把它变成新版本常驻功能；没有完成导入不能假装历史数据已迁移。
- 本次只是修改实施计划，不立即删除依赖、旧数据、密钥或进程。
- 如执行打包，仍须遵守 CLAUDE.md 的先提升 package.json 版本要求。

### 14.4 残留审计

扫描范围：electron/src、src、shared、scripts、构建配置、package.json、pnpm-lock.yaml、README/当前操作文档、干净构建产物与安装包。关键词至少覆盖 hindsight、@vectorize-io/hindsight、旧 daemon/LLM-key/golden-set IPC、memory-user/memory-project 旧接入、profile/安装脚本引用。

逐项分类而非机械要求全文零命中：

- 可执行旧后端代码、依赖或入口：必须删除，阻塞验收。
- 旧构建输出：按已核实 workspace 内路径清理后重建，确认不再生成。
- 最小一次性升级/清理识别常量：允许保留，注明用途，不含运行能力。
- 历史设计和明确选择保留的归档：允许，不能被运行时加载。
- 共享工具和缓存：列明归属豁免，不卸载。
